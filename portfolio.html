About this Project

AI Agent 平台讓企業能部署專屬的 AI 助理、自動化工作流與內部知識庫問答系統，整體規劃為三大產品線：

  • UpGPT（AI Agent）— Web 版 RAG 知識庫問答入口，非技術同仁也能用自然語言查找企業內部資訊。
  • UpAgent（AI Agent Desktop）— 桌面應用程式，能操作本機檔案、多輪推理並執行工具，適合高變異、需要互動澄清的任務。
  • Work Agent— 批次工作流引擎，處理高度重複、大量且需一致輸出的任務，支援並行批次處理。

作為主要產品設計師，我負責從概念、理解開發需求、將其轉變成介面、建立設計系統，到持續的產品體驗優化。

01 UpGPT（AI Agent） Web App

Web 版檢索增強（RAG）知識庫問答入口，暖色系對話介面，讓非技術同仁也能直接用自然語言查找企業內部資訊。

02 UpAgent（AI Agent Desktop） Desktop App

桌面應用程式，定位為「像 AI 員工一樣靈活協作」— 能操作本機檔案、多回合推理並執行工具（如 Python），適合高變異、需要互動澄清的任務。

03 Work Agent Batch Workflow

批次工作流引擎，定位為「穩定可靠的工作者」— 處理高度重複、大量且需一致輸出的任務，支援並行批次處理，以步驟條追蹤與狀態指示呈現執行進度。

Challenge

使用者端：複雜概念的心智模型

AI Agent 這個概念對大多數使用者來說是全新的 — Prompt、Tools、Memory、Workflow 這些技術語彙 若直接暴露在介面上，會造成極大的認知負擔。如何把複雜的技術概念「翻譯」成使用者看得懂的視覺語言，是最大挑戰。

產品端：從 0 開始建立設計系統

一個 SaaS 產品會有大量重複的元件（表單、表格、對話介面、節點編輯器）， 我們必須在早期就建立一套可擴充的設計系統，否則產品快速迭代時會累積大量的視覺債。

Process

1. 使用者研究與任務分析

透過訪談 10+ 位目標使用者（業務主管、行銷、客服負責人），建立出 3 個核心 Persona， 並拆解出他們最想自動化的 20+ 個任務情境，做為核心功能的優先順序依據。

2. 資訊架構與原型

以「Agent → Workflow → Task」為核心的三層資訊架構，搭配「Playground 試玩 → 發佈」的雙階段操作流程， 讓使用者可以在零風險的狀態下探索能力邊界。以 Work Agent 的「文件代理中心」為例：

3. 設計系統與元件庫

建立 100+ 個 Figma 元件，包含 tokens、typography、spacing、dark/light mode、8 種 node 類型， 供設計與工程團隊共享使用。

Learnings

AI 產品設計最大的挑戰，不是「把 AI 能做什麼呈現出來」，而是「把 AI 不能做什麼也清楚溝通出來」。 在這個專案中我們花了大量時間在設計「失敗狀態」、「降級方案」、「不確定性提示」等微互動， 這些細節才是讓使用者持續信任產品的關鍵。
