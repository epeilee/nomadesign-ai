About this Project

AI Agent
Web 版 RAG 知識庫問答入口，非技術同仁也能用自然語言查找企業內部資訊。

AI Agent Desktop
桌面應用程式，能操作本機檔案、多輪推理並執行工具，適合高變異、需要互動澄清的任務。

Work Agent
批次工作流引擎，處理高度重複、大量且需一致輸出的任務，支援並行批次處理。

作為主要產品設計師，我負責從概念、理解開發需求、將其轉變成介面、建立設計系統，到持續的產品體驗優化。

Overview

01 AI Agent

SaaS 企業知識庫問答平台，提供企業問答 Chat Agent 與可自訂流程的客製 Agent；每則回答都能查看參考資料與來源出處，搭配簡單友善的介面設計，讓非技術同仁也能用自然語言查找企業內部資訊。

02 AI Agent Desktop

桌面應用程式，定位為「像 AI 員工一樣靈活協作」— 可直接操作本機資料與檔案，例如自動整理資料夾、依年度報表產出分析統計檔；結合多回合推理與工具執行，資料全程在本機處理，機敏資料不外洩。

03 Work Agent

批次工作流引擎，定位為「穩定可靠的工作者」— 可讀取地端與雲端的大量文件，批次整理並擷取重點，一鍵匯出同意書等各式文書格式；支援並行批次處理，以步驟條與狀態指示追蹤執行進度。

Design Decisions

1. 思考過程放哪裡？AI Agent、AI Agent Desktop 兩個產品剛好相反
AI Agent：引用企業內部的知識庫，所以重點放在快速產出答案，思考過程較不重要。答案出來後，思考過程會自動切到另一個分頁。
AI Agent Desktop：需要產出報告或是結果，所以思考過程很重要。把思考步驟展開，能及時在思考過程中有錯誤時停止並矯正思考的方向，節省 token。
代價：AI Agent 使用者幾乎不會點回思考過程的分頁，過程的價值就顯現不出來。

2. Work Agent 批次：錯的資料無法帶入
Work Agent 批次讀大量資料，有資料格式不符，會在讀取結束後，帶出錯的資料筆數。失敗的檔案退回本機，改好再上傳一次，系統會自動去掉重複的。
代價：目前只帶出失敗的筆數，沒有列出是哪幾筆，使用者得自己回去檢查格式。因為有去重機制、可以只補失敗的檔案，資料完整性不受影響，所以先不做明細。

Challenge

1. AI 能力邊界模糊，難以預判產出品質
在專案初期，無法準確掌握 AI 生成內容的品質上限與穩定性，導致設計規劃時難以評估哪些任務可以放心交給 AI、哪些仍需人工把關。

2. 原始設計素材的掌控權疑慮
提供設計稿作為 AI 訓練或參考素材時，設計師難以確保 AI 不會擅自更動風格、版型或視覺邏輯，原創設計的一致性與可控性受到挑戰。

3. 工作流程根本轉變：從「讀懂 PM Brief」到「讀懂規格文件」
過去設計師的輸入來源是 PM 撰寫的需求說明，現在核心輸入變成給 AI 讀取的規格文件（md 檔）。這類文件是為機器解析而寫，邏輯結構、專業術語密度都與人類溝通習慣不同，設計師必須同時扮演「讀懂機器語言」與「產出人性化設計」兩種角色，學習成本大幅提高。

4. 設計產出與規格文件的一致性核對
每次交付都需要額外花時間逐項核對設計結果是否確實符合 md 規格文件的定義，增加了設計流程中的驗證環節，也考驗設計師對規格的解讀能力。

5. 交付檔案與實際開發結果的落差
即使設計稿與規格文件完全吻合，也無法保證開發實作後的成品與設計檔案 100% 一致。這種「所見非所得」的落差，是目前 AI 導向設計流程中最核心、也最難解決的問題。

Advantage

1. 具備基礎前端知識，讓人機協作更精準
具備 HTML／CSS 的基本理解與操作能力，讓我在調整設計時能用自然語言與語法互相輔助溝通，大幅提升與 AI 協作修改介面的效率與準確度。

2. Figma 與 Claude Design 相輔相成
善用 Figma 搭配 Claude Design 協作，能快速產出高度符合規格與視覺樣式的設計稿，兩者截長補短，兼顧效率與品質。

3. 即時請教 AI，邊做邊學
遇到問題時直接請 AI 分析並提出多種解決方案，不僅加快決策速度，也讓自己在實作過程中持續累積新知識與解法。

4. 跨足設計、開發、測試技能，節省設計時間
主動學習設計、開發與測試相關技能，讓自己能更全面地掌握產品從規劃到落地的每個環節，大幅節省重複溝通與返工的設計時間。
