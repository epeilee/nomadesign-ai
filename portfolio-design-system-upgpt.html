Design Tokens

Token Architecture

本設計系統採用與 SGDS 相同的五層 Token 架構。每層引用下一層， 修改單一 Primitive 值即可透過整個系統傳遞，確保設計與程式碼的一致性。

1
Raw Value
#14C6DE
實際的原始值（顏色碼、px 值等），不直接在元件中使用。
2
Primitive Token
--upgpt-cyan-500
基礎設計決策，定義色階、間距刻度、字型大小等核心值。
3
Simplified Semantic
--upgpt-primary-bg-default
語意化別名，描述「用途」而非「值」，跨元件通用。
4
Granular Semantic
--upgpt-btn-primary-bg-default
針對特定情境的語意 Token，如 form、action、feedback。
5
Component-specific
--upgpt-btn-label-padding-x
元件專屬 Token，供個別元件微調，引用上層 Token。

Token 命名規則

採用四段式命名：namespace · object · base · modifier

upgpt
Namespace — 系統識別符
primary / btn / form
Object — 套用對象或情境
bg / color / padding
Base — 設計屬性或角色
default / hover / md
Modifier — 狀態、強調或尺寸

Motion

Motion（動態）

Layer

Z-index / 層級系統

統一的堆疊順序 Token，避免各元件使用任意 z-index 值導致衝突。 從 base 到 floating 共六個層級，對應不同的 UI 元件類型。

Token Value 用途
--upgpt-z-index-base0一般頁面元素
--upgpt-z-index-raised10Sticky header, 略為浮起的元件
--upgpt-z-index-dropdown100下拉選單、Popover
--upgpt-z-index-overlay200背景遮罩 Overlay
--upgpt-z-index-modal300Modal 對話框
--upgpt-z-index-tooltip400Tooltip 提示文字
--upgpt-z-index-floating500最高層浮動元件（通知、Toast）
Theme

三產品 Theme 系統

透過 data-theme 屬性切換，同一套 Semantic Token 在不同 Theme 下映射到不同的 Primitive 色值，元件程式碼無需修改。 點擊頁面頂部的 Preview Theme 按鈕即可即時切換。

Governance

Token Change Impact

不同層級的 Token 修改，影響範圍與風險程度差異很大。 修改前務必評估下表中的層級、影響範圍與建議流程。

Token 層級 影響 風險 適用情境 建議流程
Primitive Token
--upgpt-cyan-500		 High
更動所有引用它的 Semantic Token，影響整個產品線		 可能造成視覺 bug 或可及性問題 品牌色更新、可及性對比度修正 盤點所有引用 → Staging 測試 → 公告遷移
Semantic Token（通用）
--upgpt-primary-bg-default		 High
影響所有使用此語意角色的元件		 跨元件視覺不一致 互動狀態調整、主題更新 審查元件清單 → 提案說明 → Staging 驗證
Semantic Token（情境）
--upgpt-btn-primary-bg-default		 Medium
只影響特定元件或情境		 局部視覺變化，較易控制 單一元件微調、情境差異化 確認元件使用範圍 → PR Review
Component Token
--upgpt-btn-label-padding-x		 Low
只影響單一元件的特定屬性		 低風險，通常為局部調整 元件版面微調、尺寸更新 元件測試 → 合併
新增 Token Low
不影響現有 Token，擴充系統		 Token 數量增加，需避免重複 新元件需求、情境擴充 確認無重複 → 命名審查 → 文件更新
棄用 Token Medium
可能導致引用方報錯		 Deprecated 若未公告，會破壞相依 清理廢棄 Token、命名統一 標記 deprecated → 公告期 → 確認無引用後移除
