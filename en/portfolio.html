About this Project

AI Agent
A web-based RAG knowledge Q&A entry point that lets non-technical staff search internal company information in natural language.

AI Agent Desktop
A desktop app that works with local files, multi-turn reasoning, and tool execution — built for high-variance tasks that need interactive clarification.

Work Agent
A batch workflow engine for highly repetitive, high-volume tasks that need consistent output, with support for parallel batch processing.

As lead product designer, I owned the process end to end — from concept and requirements interpretation, through interface design and building the design system, to ongoing product experience refinement.

Overview

01 AI Agent

A SaaS enterprise knowledge Q&A platform offering a Chat Agent for general questions and customizable Advanced Agents; every answer surfaces its reference sources, with a simple, approachable interface that lets non-technical staff search internal information in natural language.

02 AI Agent Desktop

A desktop app positioned as "a flexible AI coworker" — it works directly with local data and files, from auto-organizing folders to producing analysis reports from annual data. It combines multi-turn reasoning with tool execution, and all data stays local so sensitive information never leaves the machine.

03 Work Agent

A batch workflow engine positioned as "a reliable, steady worker" — it reads large volumes of local and cloud documents, batch-extracts key data, and exports consent forms and other document formats in one click. It supports parallel batch processing, with progress bars and status indicators tracking execution.

Design Decisions

1. Where does the reasoning trace live? AI Agent and AI Agent Desktop take opposite approaches
AI Agent: it draws on the internal knowledge base, so the priority is producing an answer fast — the reasoning trace matters less. Once the answer lands, the trace auto-switches to a separate tab.
AI Agent Desktop: it needs to produce reports or results, so the reasoning trace matters a lot. Expanding the reasoning steps lets a user stop and correct course the moment something looks wrong, saving tokens.
Trade-off: AI Agent users rarely click into that trace tab, so its value there barely shows up.

2. Work Agent batch runs: bad rows can't be carried through
When Work Agent batch-reads large datasets, mismatched-format rows are flagged as failed once the read completes. Failed files are returned locally, fixed, and re-uploaded — the system automatically dedupes.
Trade-off: today it only reports the failed count, not which rows failed, so users have to check the formatting themselves. Because the dedup mechanism lets users re-upload just the failed files without affecting data integrity, a detailed breakdown wasn't built for now.

Challenge

1. Blurry boundaries on what AI can do, making output quality hard to predict
Early in the project, it was hard to gauge the ceiling and consistency of AI-generated content, which made it difficult to judge which tasks could safely go to AI and which still needed human review.

2. Concerns over control of original design assets
When design files are used as AI training or reference material, it's hard for a designer to guarantee AI won't alter the style, layout, or visual logic on its own — challenging the consistency and control of the original design.

3. A fundamental workflow shift: from "reading the PM brief" to "reading the spec document"
Designers used to work from requirements written by a PM; now the core input is a spec document (an .md file) written for AI to parse. These documents are written for machine parsing — their logical structure and density of technical terms differ from how humans communicate, so a designer now has to both "read machine language" and "produce human-centered design" at once, raising the learning curve substantially.

4. Cross-checking design output against the spec document
Every handoff now takes extra time to verify, line by line, that the design output actually matches what the .md spec defines — adding a verification step to the design process and testing how well a designer can interpret the spec.

5. The gap between delivered files and the actual build
Even when a design file matches its spec exactly, there's no guarantee the built product will match the design 100%. This "what you see isn't what you get" gap is the most central, and hardest to solve, problem in an AI-driven design workflow today.

Advantage

1. A working knowledge of front-end fundamentals makes human-AI collaboration sharper
A basic understanding of HTML/CSS lets me communicate design changes using both natural language and syntax, greatly improving the speed and accuracy of collaborating with AI on interface changes.

2. Figma and Claude Design complement each other
Pairing Figma with Claude Design produces designs that closely match spec and visual style quickly — each tool covers the other's gaps, balancing speed and quality.

3. Consulting AI in real time, learning while building
When something comes up, I ask AI to analyze it and propose several solutions on the spot — speeding up decisions while continuously building new knowledge and problem-solving skills along the way.

4. Skills spanning design, development, and testing save design time
Proactively picking up design, development, and testing skills gives me a fuller grasp of every stage from planning to shipping, cutting significant time spent on repeated back-and-forth and rework.
